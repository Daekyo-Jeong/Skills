# dkdk 본문 삽화

## 핵심 포지션

한국어 글을 위한 16:9 가로 본문 삽화를 설계·생성한다. 상업 일러스트, PPT 인포그래픽, 귀여운 카툰이 아니라 — 글 속의 핵심 판단·흐름·구조·상태·은유 하나를 깔끔하고 엉뚱하고 기억에 남는 손그림 설명 이미지로 바꾸는 것이 목표.

고정 비주얼 IP는 "dkdk": 의인화된 바다코끼리 자화상. 점눈, 뭉툭한 엄니, 브라운 웰링턴 안경, 맨번, 다크 티셔츠. 마스코트가 아니라 진지한 표정으로 약간 황당한 일을 수행하는 시스템 오퍼레이터다. dkdk는 반드시 화면의 핵심 동작에 참여해야 하고, 옆에 서 있는 장식이면 실패다.

## 먼저 읽을 레퍼런스

필요한 것만 읽는다. 한 번에 다 채우지 말 것:

- `references/style-dna.md`: 스타일 DNA, 색, 텍스트, 금기.
- `references/dkdk-ip.md`: dkdk IP의 외형·성격·동작 풀·금기.
- `references/composition-patterns.md`: 구조 유형, 은유 발명법, 복제 금지 규칙.
- `references/prompt-template.md`: 장당 생성 프롬프트 템플릿.
- `references/qa-checklist.md`: 생성 후 검수와 반복 규칙.
- 아이덴티티 기준 이미지: `assets/dkdk-board-ink-bw.png` (순수 흑백 잉크 모델시트 — 검정/흰색 2값, 검정끼리 겹치는 경계는 흰 라인). 생성 시 `-i`로 첨부하는 기준. 그레이 톤 버전은 `assets/dkdk-board-bw.png`.
- `assets/examples/`: 완성 예시. 저빈도 시각 캘리브레이션 전용 — 구도·물건·라벨을 베끼지 말 것.

## 워크플로

### 1. 본문 소화

사용자가 준 본문·링크·Notion 페이지·Markdown·스크린샷을 먼저 읽는다. 추출할 것:

- 핵심 주장이 무엇인가
- 어느 문단이 인지적 전환을 담당하는가
- 어떤 내용이 그림으로 설명하기 적합한가
- 어디는 글만으로 충분한가

균등 배분하지 말 것. "인지 앵커"를 우선한다: 핵심 판단, 끊어지는 지점, 입출력 루프, 분기, 전후 대비, 하나를 여러 용도로 쓰기, 인계 경로, 흔한 함정, 상태 변화.

### 2. shot list 먼저

사용자가 "어디에 삽화 넣을지 분석해줘" 수준이면 shot list부터. 장마다:

- 어느 문단 뒤에 놓는가
- 주제
- 핵심 의미
- 구조 유형
- dkdk가 그림에서 뭘 하는가
- 제안 요소
- 제안 한글 라벨

기본 4-8장. 짧은 글은 1-3장, 긴 글도 9장은 넘기지 않는다. 본문을 화보집으로 만들지 말 것.

### 3. 장당 생성 (easel 백엔드)

사용자가 명시적으로 "생성해줘/만들어줘"라고 하면 확인 기다리지 말고 진행한다. 여러 장을 한 이미지에 합치지 말고 **한 장 = 한 번의 생성**.

이 환경의 생성 백엔드는 easel의 gen.sh다 (Codex 앱 + ocx 프록시, API 키 불필요). **반드시 모델시트를 `-i`로 첨부해서** 생성기가 캐릭터 기준 이미지를 직접 보게 한다 — 텍스트 묘사만으로는 얼굴 일관성이 무너진다:

1. 장마다 `./brief/<slug>-NN.md` 브리프 파일을 쓴다. 내용은 `references/prompt-template.md`를 채운 완성 프롬프트 (캐릭터 아이덴티티 레퍼런스 블록 포함 — 템플릿 참조).
2. 실행 — **반드시 run_in_background로** (장당 60~110초, 여러 장 병렬 가능):

   ```bash
   GENSH="$(dirname "$(readlink -f "$(which easel)")")/scripts/gen.sh"
   SHEET="<이 스킬 폴더>/assets/dkdk-board-ink-bw.png"
   cat ./brief/<slug>-NN.md | "$GENSH" ./runs/<slug>-NN.png -i "$SHEET"
   ```

3. 백엔드 연결 에러(connection refused) 시 `ocx ensure`로 프록시 띄우고 재시도.
4. 수정 반복: 브리프를 고쳐 재실행하거나, 직전 결과를 유지·수정하려면 `-i "$SHEET" -i <직전결과.png>`처럼 둘 다 첨부하고 브리프에 수정 지시를 덧붙인다.

프롬프트에 반드시 포함: 16:9 가로 / 순백 배경 / 검정 손그림 선화 / 소량의 빨강·주황·파랑 한글 손글씨 주석 / 넉넉한 여백 / dkdk가 핵심 동작의 주체 / PPT·상업 일러스트·유치한 귀여움·복잡한 다이어그램·좌상단 유형 제목 금지.

과거 사례를 복제하지 말 것. 매번 지금 글에서 엉뚱하지만 성립하는 은유를 새로 발명한다.

### 4. 검수와 반복

생성 후 `references/qa-checklist.md`로 검사. 다음이 보이면 재생성 또는 부분 수정 우선:

- dkdk가 장식으로만 존재
- 화면이 너무 가득 참
- 플로차트/PPT처럼 보임
- 한글이 너무 많거나 오타 심함 (한글은 이미지 모델에서 잘 깨진다 — 라벨 수를 줄여 재생성)
- 좌상단에 "워크플로/시스템 구조도" 같은 유형 제목 등장
- 그림이 귀엽거나 유치하거나 뻣뻣함
- 배경이 깨끗한 백지가 아님

### 5. 저장·전달

최종 이미지를 작업 폴더의 `assets/<article-slug>-illustrations/`에 복사한다:

```text
01-topic-name.png
02-topic-name.png
```

원본 생성 파일(runs/)은 남겨두고, 기존 자산은 명시적 요청 없이 덮어쓰지 않는다.

## 출력 톤

생성 전 전략 출력은 짧고 정확하게. 생성 후 전달에는 포함:

- 몇 장 생성했는지
- 각 장의 용도
- 저장 경로
- 어떤 장이 안정적이고 어떤 장이 선택지인지

스타일 이론을 길게 설명하지 말 것. 그림이 말하게 한다.
