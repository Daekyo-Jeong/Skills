# boardgame-port

물리 보드게임을 dkdk-arcade로 이식할 때의 작업 순서와 불변 원칙. DEFRAG(Galdor's Grip)·OVERLAY(Orchard)·PENTOMINO에서 실제로 밟아 확정된 것들이다.

## 0. 불변 원칙 (전 단계에 적용)

1. **밸런스 수치 불변** — 룰만 가져오고 숫자는 원작 그대로. 승리 임계·카드 값·제한 개수를 임의로 바꾸지 않는다.
2. **저작권 경계** — 메커니즘만 이식. 이름·테마·카드명·능력 텍스트·아트는 전부 자체 창작. 구매한 룰 PDF는 `reference/`에 두고 `.gitignore`(커밋 히스토리에도 남기지 않는다).
3. **정보 권한 등가** — 원작이 주는 정보를 줄이지도 늘리지도 않는다(§3).
4. **확장보다 완주** — 콘텐츠 추가 전에 '한 판을 온전히 플레이 가능한 상태'(크래시·정보 누수·모바일 조작·종료 화면)가 먼저. plan.md 다음 항목이 '확장'이면 완주 가능성부터 점검하고 제안한다.

## 1. 소스 확보 (착수 조건)

이식 시작 전에 두 가지를 먼저 확보한다:

- ① **공식 룰 PDF 원문** — 블로그·요약 사이트는 핵심 수치가 서로 어긋난다(Orchard 실사례: 주사위 진행 1→3→6 vs 1→3→6→10, 원문으로만 확정). 2차 요약으로 확정 금지.
- ② **원본 카드 이미지** — 텍스트 요약은 ⟳ 심볼 유무, ★가 어느 면에 인쇄됐는지, 능력 박스가 어느 면에 있는지 같은 **그림에만 있는 정보**를 반드시 잃는다. PDF→PNG로 직접 렌더해서 대조한다(홀수 쪽만 앞면인 스캔 구조 등도 먼저 확인).

못 구한 항목은 **'원본과 다를 수 있는 지점'으로 명시 기록**하고, 대체 데이터는 원작과 같은 제약을 만족하도록 생성해 교체 가능한 한 파일에 격리한다(OVERLAY: 카드 18장 배열을 시드 고정 생성 → `data.ts` 배열만 갈아끼우면 교체).

## 2. 리스킨 대응표 (정본 문서)

원작 용어 → 아케이드 테마 용어 대응표를 먼저 확정하고, 이후 모든 카드 추가·문구 작성은 이 표의 어휘로만 한다.

예시 — OVERLAY(Orchard): 과일나무 3종→CMY 채널 노드(초록 금지라 RGB 아님), 주사위→GAIN 칩, 썩은 과일→DEAD PIXEL, 수확 등급→NO SIGNAL→…→PERFECT SYNC. / DEFRAG(Galdor's Grip): 디스크 조각모음 테마(ANCHOR·BOOT SECTOR·BAD SECTOR·READ HEAD·GLITCH…).

대응표는 코드만 봐서는 복원이 안 되므로 engram에 기록한다.

## 3. 정보 등가성 체크리스트

이식의 각 시점마다 "**물리 카드였다면 지금 뭘 볼 수 있나?**"를 나열하고 화면과 대조한다:

- 카드에 함께 인쇄된 정보(회전면 값·★·능력)는 **조작 없이** 한눈에 — 큰 카드엔 정보 박스, 작은 카드엔 축약 표기.
- 앞면 카드는 어디서든(덱 보기·NEXT·넘기기 단계) 같은 상세 열람 — 상세 컴포넌트 하나를 공유.
- peek(엿보기)은 카드를 **보는** 것 — 이름만 주면 룰보다 불리하다. 값·능력 전부 연다.
- 반대로 뒷면(비공개) 카드 정보가 UI에 새면 정보 누수 — `?`로 가리고 합계에서도 제외.
- 여러 단계가 있는 카드(1/3·2/3)는 단계 표시를 붙여 상태를 읽히게.

## 4. 모바일 조작 규칙

- **화면 분할 금지, 시트가 덮는다** — 단계형 조작은 하단 시트가 화면을 먹고 올라온다(상단 ~13%만 남김, 무대는 딤+조작 차단, 딤 탭으로 닫힘). 되돌릴 수 없는 단계에선 상단 조작을 아예 제거해 절차를 강제.
- 시트 안에서 상세를 띄울 땐 `createPortal`로 body에 — transform 걸린 조상은 `position:fixed`의 기준이 되어 상세가 시트 안에 갇힌다.
- **조작 dock은 고정 높이·고정 위치, 내용만 교체** — 상태 문구가 버튼을 밀면 문구를 버린다. 상태는 색·테두리로 말하게 하고, 조작을 문장으로 설명해야 한다면 UI가 진 것.
- 화면은 100dvh에 가두고 보드가 남는 공간에 맞춰 축소 — 조작하려고 스크롤하는 일이 없게.
- **배치형 퍼즐은 고스트(미리보기)가 1급 상태** — 어디를 탭해도 반투명 고스트가 뜨고(밖이면 안으로 당김), 겹치면 고스트는 남기고 확정만 막으며 붉게 표시. '무반응'은 금지가 아니라 버그로 읽힌다. 회전·뒤집기는 고스트 위에서 결과가 보여야 존재하는 기능이 된다.

## 5. 비주얼

- 팔레트 정본: accent **#00AAFF**(애저, 주조) + accent-2 **#FF9900**(오렌지, 보조) + #999999(뉴트럴). **초록 계열 금지**(lab neon green 금지 조항). 기각된 안(앰버+마젠타, 민트 단색, 시안+코랄)을 재제안하지 않는다.
- 색 판정 자는 목적별로: 텍스트 가독성=WCAG 대비, 토큰 간 구분=**ΔE**, 팔레트 단색 붕괴=색상각 분포. WCAG만 보면 hue가 달라도 안 잡힌다.

## 6. 검증 (룰 대조 + 기계 검증)

1. **룰 감사**: 텍스트 레퍼런스로 1차 → **원본 카드 이미지로 2차**(1차에서 안 잡히는 오류가 실제로 나온다).
2. **퍼즈**: 무작위 수천 판(기준: 5,000판급) 돌려 크래시 0 확인. 모드·덱 구성이 여러 개면 모드별로(기준: 5모드 × 600판).
3. **승리 가능성**: 1수 탐욕 봇 수백 판 — 승률이 0이면 이식이 틀린 것(DEFRAG 기준: 300판 중 25승).
4. 교착·즉시 패배 같은 엣지 룰은 실발동 케이스를 만들어 확인.

## 7. 배포

- 레포: `Daekyo-Jeong/dkdk-arcade`(main) → **push하면 Vercel 자동 배포**로 `arcade.dkdk.me` 즉시 반영(`/g/<game>`). 커밋은 자유, **push는 대교 확인 후**.
- 로컬 dev(`npm run dev`)는 OAuth 게이트가 안 걸려 바로 확인 가능.
- 확장 세트를 붙일 땐 덱 구성 선택(CORE / 확장별 / RANDOM)과 원작의 고정/교체 카드 구조를 따른다.

## 8. 마무리

이식이 끝나면 리스킨 대응표·원본과 다른 지점·검증 수치(퍼즈 판수, 봇 승률)를 engram에 기록한다 — 다음 이식과 후속 감사가 이 문서와 그 기록에서 시작한다.
