# [프로젝트명] Design Brief

> 함께 읽을 문서: [spec.md](spec.md) — 제품의 무엇/왜/동작은 거기. 이 문서는 비주얼만.

## 1. 한 줄 소개 + 대상
- 무엇을 위한 화면이고 누가 쓰는가.

## 2. 현재 상태 / 불편점
- (리디자인이면) 지금 무엇이 아쉬운가. 신규면 생략 가능.

## 3. 디자인 원칙
- 이 제품이 지켜야 할 비주얼 축 5~7개 (예: 정보 밀도, 무드, 레트로/모던, 모션 톤 등).
- 레퍼런스/무드보드가 있으면 링크.

## 4. 페이지 / 컴포넌트 인벤토리
| 화면·컴포넌트 | 목적 | 핵심 요소 | 우선순위 |
|---|---|---|---|
| | | | |

## 5. 비주얼 시스템 (토큰)
- **컬러**: 역할별(배경/전경/강조/상태) 값. spec에 정의된 게 있으면 그대로 따른다.
- **타이포**: 폰트, 위계(헤딩/본문/캡션).
- **간격 · 라운드 · 그림자**: 기본 스케일.

## 6. 제약
- 해상도/뷰포트, 반응형 범위, 접근성, 다크/라이트, 기술적 한계.

## 7. 산출물 형식
- 받을 결과를 구체적으로: Figma 파일 / HTML+CSS / SVG / PNG 시안 / 토큰 JSON 중 무엇인지.
- 화면 수, 상태(빈/로딩/에러) 포함 여부.

## 8. ❌ 하지 말 것
- 임의 새 팔레트 정의 금지 (spec/토큰 따를 것)
- 스코프 밖 화면 만들지 말 것
- spec의 동작 규칙을 비주얼로 임의 변경하지 말 것
- (프로젝트별 금지사항 추가)
