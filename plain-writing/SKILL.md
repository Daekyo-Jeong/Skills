# Plain Writing — 쉽게 + 사람같이

읽는 사람이 한 번에 이해하고, 사람이 쓴 것처럼 자연스러운 글을 만든다. 목표는 두 개다: **소통성**(쉽게 읽힘)과 **정확성**(뜻이 안 흐트러짐). 쉬운언어와 "AI 티 안 나게"는 대부분 같은 것을 가리킨다 — 번역투·과장·군더더기를 걷어내면 둘 다 해결된다.

이 스킬은 **쓸 때**와 **고칠 때** 모두 쓴다. 새 글을 쓰면 처음부터 이 원칙대로 쓰고, 남의 글이나 AI 초안을 받으면 아래 기준으로 다듬는다.

## 먼저 지킬 것 — 뜻은 건드리지 않는다

문체를 고치는 것이지 내용을 바꾸는 게 아니다. 다음은 절대 바꾸거나 지어내지 않는다.

- **수치·단위·날짜** — "약 30%"를 "상당수"로 뭉개지 않는다.
- **고유명사·인명·제품명·모델명**
- **큰따옴표 안 직접 인용** — 인용문은 원문 그대로 둔다.
- **법·규정 조문**, 계약·약관 문구
- **불가피한 전문 개념어** — 풀어쓰면 뜻이 달라지는 학술어는 남긴다.
- **문체(존댓말/평어)** — 원문이 합쇼체면 합쇼체로, 평어면 평어로 고친다. 종결어미 톤을 마음대로 바꾸지 않는다.

그리고 **장르를 옮기지 않는다.** 보고서를 에세이로, 공지를 광고 문구로 바꾸지 않는다. 고칠 때는 **문제가 있는 부분만** 손대고, 멀쩡한 문장은 그대로 둔다. 글 전체를 절반 넘게 새로 쓰고 있다면 과교정이니 멈추고 원문 톤으로 돌아간다.

## 1. 쉽게 쓰는 규칙

**핵심을 맨 앞에.** 문서도 문단도 문장도 결론·요점을 먼저 놓는다. 읽는 사람이 첫 줄만 봐도 무슨 얘긴지 알게 한다.

**한 문장에 한 생각.** 문장이 길어지면 자른다. 한 문장이 60자를 넘으면 둘로 나눌 수 있는지 본다. 접속사로 계속 잇지 말고 마침표를 찍는다.

**능동태로.** "데이터를 검토했다"(O) / "데이터가 검토되었다"(X). "~에 의해 ~되다"가 보이면 누가 했는지 드러내 능동으로 바꾼다. 단, 행위자가 정말 중요하지 않거나 관행상 피동이 자연스러운 경우(예: "예산이 삭감됐다")까지 억지로 바꾸지는 않는다.

**전문어·약어는 풀어쓴다.** 처음 나오는 낯선 용어는 쉬운 말로 바꾸거나 한 번 풀어준다. 라틴·영어 약어는 우리말로: e.g.→"예를 들어", i.e.→"즉", etc.→"~ 등", via→"~로".

**군더더기를 자른다.** 빼도 뜻이 같으면 뺀다. 이게 이 스킬의 핵심 동작이다. "~하는 것", "~에 대한", "~을 통하여", "~라고 할 수 있다" 같은 말은 대개 지우거나 짧게 줄일 수 있다.

**읽는 사람은 "여러분/당신", 나는 "우리".** 막연한 3인칭보다 직접 부르는 편이 잘 읽힌다.

## 2. 한국어 번역투 다듬기 (맥락 기반 — 기계적 치환 금지)

아래는 **바꿀 후보**지 자동 치환 규칙이 아니다. 문맥을 보고 자연스러운 쪽을 고른다. 공문서에서 자연스러우면 그대로 둬도 된다. 뜻이 바뀔 것 같으면 바꾸지 않는다.

| 번역투/딱딱한 말 | 고쳐 쓰기 후보 |
|---|---|
| ~을 통해 / ~를 통하여 (남발) | ~로, ~으로, (자주 생략 가능) |
| ~에 있어서 | ~에서, ~에게, (생략) |
| ~로부터 | ~에서, ~에게서 |
| ~에 대한 / ~에 대해 (남발) | ~의, ~을, (생략) |
| ~와 관련하여 | ~에 대해, ~은/는 |
| ~에 기반하여 | ~를 바탕으로, ~에 따라 |
| ~하는 것 (과한 명사화) | ~하기, 또는 동사로 풀기 |
| ~을 진행/수행/실시하다 | ~하다 (회의를 진행하다 → 회의하다) |
| 활용하다 | 쓰다, 사용하다 |
| 제공하다 (남발) | 주다 |
| ~을 위한 | ~에 쓸, ~용 |
| 및 (남발) | ~와/과, 그리고 |
| ~인 것으로 나타났다/보인다 | ~다 |
| 극대화하다 | 최대한 키우다 |
| ~에 의해 ~되다 (피동) | 누가 했는지 드러내 능동으로 |
| ~되어지다 (이중 피동) | ~되다 |
| 그/그녀 (영어 대명사 직역) | 이름을 쓰거나 생략 |

**조사·수식이 겹겹이 쌓인 번역투**도 푼다. "~에서의/~로의/~에로의" 같은 이중 조사, 관형절이 3중으로 앞에 붙은 긴 수식은 문장을 끊어 풀어낸다.

## 3. AI 티 안 나게

AI가 쓴 글의 티는 크게 내용·형식·리듬에서 난다. 아래가 보이면 걷어낸다. (분류 뼈대는 Wikipedia "Signs of AI writing", 오픈소스 `im-not-ai`(MIT) 분류표, 국립국어원 공공언어 원리를 참고했다.)

**내용 티 — 과장과 공허한 마무리**

- 과장/상투구: "~라는 점에서 (큰) 의미가 있다", "~의 중요성을 강조한다", "주목할 만하다", "시사하는 바가 크다", "핵심적인 역할을 한다", "혁신적인/획기적인/전례 없는"
- 정형 결론: "결론적으로", "종합하면", "요컨대"를 습관처럼 붙이지 않는다.
- 부정 병렬(영어 not just X but Y의 번역): "단순한 ~가 아니라 ~다", "~를 넘어 ~로"
- 애매한 출처: "전문가들은 ~라고 말한다", "일각에서는", "~로 알려져 있다" — 누구인지 못 대면 빼거나 출처를 밝힌다.
- 얄팍한 연결: "~을 시사하며", "~을 보여주며", "~을 반영하며"로 문장을 억지로 잇지 않는다.
- 영어 원문: puffery("stands as a pivotal moment", "underscores the importance of"), tell-words 뭉치(delve, underscore, tapestry, pivotal, robust, leverage, boasts, meticulous, testament, vibrant, foster, showcase) — 한 글에 여러 개 뭉치면 강한 신호.

**형식 티**

- 모든 핵심어를 **볼드** 처리하지 않는다. 강조는 정말 필요한 데만.
- em대시(—)를 쉼표·괄호·콜론 자리까지 남발하지 않는다.
- 볼드 헤더 + 콜론 리스트("**항목**: 설명")를 기계적으로 반복하지 않는다.
- 이모지를 불릿이나 구분자로 쓰지 않는다.
- 기계적으로 3개씩 나열(rule of three)하지 않는다. 필요한 만큼만 든다.
- 감탄사(!)로 힘주지 않는다.
- 제목을 영어 Title Case로 모든 단어 대문자 처리하지 않는다.

**리듬 티**

- 문장 길이가 다 비슷하면 지루하다. 짧은 문장과 조금 긴 문장을 섞는다.
- 같은 종결어미("~습니다", "~합니다")가 연달아 반복되면 바꿔준다.
- 문두에 "또한/따라서/즉/나아가"를 계속 붙이지 않는다.
- 불필요한 부사(매우, 굉장히, 정말, 너무)는 뺀다. 대개 없어도 된다.
- 완곡 표현을 겹쳐 쓰지 않는다: "~할 수 있을 것으로 보인다" → "~할 수 있다" 또는 단정.
- 형식명사 남발("~것이다", "~라는 점", "~할 필요가 있다")을 줄인다.

## 4. 끝내기 전 셀프체크

글을 마치기 전에 스스로 확인한다.

1. 가장 중요한 내용이 맨 앞에 있나?
2. 비전문가가 각 문장을 한 번 읽고 이해하나?
3. 문장이 능동·짧고·한 생각씩인가?
4. 번역투·전문어·라틴약어·과장·마케팅 톤을 걷어냈나?
5. 볼드/이모지/대시/기계적 나열 같은 형식 티가 없나?
6. 제목과 링크가 내용을 설명하나? ("여기 클릭" X)
7. **더 뺄 단어가 있나? 있으면 뺀다.**
8. 수치·고유명사·인용·문체 등 원문의 사실과 톤이 그대로인가?

## 5. 무거운 사후 윤문은 im-not-ai로

이미 완성된 긴 AI 글을 정밀하게 윤문(변경률·심각도 관리, 의미 동등성 감사까지)해야 하면, 전용 오픈소스 도구 `im-not-ai`(Humanize KR, MIT, Claude Code 플러그인)를 쓰는 편이 낫다. 번역투를 수십 개 패턴으로 세분해 탐지하고 롤백·품질등급까지 한다.

이 스킬은 **쓸 때 처음부터 쉽고 사람같이** 쓰는 데, im-not-ai는 **사후 정밀 윤문**에 강하다. 사용자가 "완성된 초안을 통째로 자연스럽게 다듬어달라"고 하면 im-not-ai 설치를 권한다.

설치: Claude Code에서 `/plugin marketplace add epoko77-ai/im-not-ai` → `/plugin install humanize-korean@im-not-ai`.

## 예시

**번역투 + 군더더기**
- 전: "AI 기술을 통해 업무 효율을 향상시킬 수 있다."
- 후: "AI로 업무 효율을 높인다."

**피동 + 공허한 마무리**
- 전: "이번 결과는 시장의 변화가 반영된 것으로 볼 수 있으며, 결론적으로 시사하는 바가 크다."
- 후: "이번 결과는 시장이 변했다는 뜻이다." (또는 무엇을 시사하는지 구체적으로 쓴다)

**형식 티 + 과장**
- 전: "**핵심 전략**: 우리는 혁신적이고, 강력하며, 압도적인 솔루션을 제공합니다 — 고객을 위해."
- 후: "우리 전략은 고객이 실제로 쓸 만한 제품을 만드는 것이다."

**과한 명사화**
- 전: "비용 절감을 위한 방안 마련이 필요한 상황이다."
- 후: "비용을 줄일 방법을 찾아야 한다."

## 메타 — 이 스킬을 쓰는 너에게

이 문서 자체도 위 규칙을 지키려 했다. 글을 고칠 때 규칙을 하나하나 기계적으로 대입하지 말고, "읽는 사람이 한 번에 이해하고, 사람이 쓴 것처럼 읽히는가"를 기준으로 판단해라. 규칙은 그 판단을 돕는 체크리스트지 목적이 아니다. 확신이 안 서면 원문을 덜 건드리는 쪽을 고른다 — 과교정보다 조금 남기는 게 낫다.
