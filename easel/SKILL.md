# easel — 발산-선택-수렴 디자인 루프

브리프에서 이미지를 `발산 → 사람이 픽 + 코멘트 → 정체성 유지 수렴`으로 다듬는 독립 CLI. **사람이 디렉터** — Claude는 프롬프트를 짜고(손), Codex가 그리며, 고르고 방향 잡는 건 사람.

## 언제 쓰나
사용자가 마스코트·로고·일러스트·목업 등 이미지 시안을 **반복해서 다듬으려** 할 때. 단발 "이미지 하나"가 아니라 여러 후보를 뽑아 고르고 코멘트로 좁히는 워크플로.

**쓰지 않을 때**: 단순 이미지 1장 생성, SVG/코드 네이티브 그래픽, 텍스트 작업.

## 요구
- macOS · **Codex 데스크탑 앱**(ChatGPT 구독 로그인) · `claude` CLI. API 키 불필요.
- `easel`가 PATH에 설치돼 있음(`which easel`로 확인). 어느 폴더에서든 `easel`로 호출된다.

## ⚠️ 실행 위치 = 결과 위치 (중요)
`easel`은 결과를 **호출한 현재 작업 폴더 기준 `./runs/<id>/`**에 쓴다(설치/소스 폴더가 아니라). 그래서:

- **반드시 사용자의 현재 세션 폴더에서 그대로 실행하라.** easel이 설치된 폴더로 `cd` 하지 마라 — 그러면 결과가 그 폴더에 갇힌다.
- **brief도 현재 폴더에 `./brief/<name>.md`로 새로 작성하라.** easel 소스 폴더에 있는 예시 brief를 가져다 쓰지 마라(그 폴더로 끌려가는 원인).
- `start`와 `continue`는 **같은 폴더에서** 실행해야 한다(continue가 `./runs`에서 직전 라운드를 찾는다).
- 다른 위치에 저장하려면 `EASEL_RUNS=<dir>`로 덮어쓴다.

## 사용법
1. 디자인 의도를 **현재 폴더의** `./brief/<name>.md`로 작성 (대상·톤·스타일·제약 등 구체적으로).
2. 실행 (현재 폴더에서, **`run_in_background`로** — 느리다):
   - `easel start ./brief/<name>.md` — N장 발산. 끝나면 로그에 `results → <경로>`.
   - `easel continue --pick <n> [--note "발전 방향"]` — 고른 후보를 정체성 유지하며 수렴. note로 방향 지시(생략 시 가벼운 변주).
3. **★ 라운드가 끝나면 그 round의 후보 PNG를 전부 `Read` 도구로 읽어 채팅에 띄운다** — `./runs/<id>/roundN/r{N}_1.png … r{N}_K.png`(번호 순서대로 한 번에). 사용자가 **채팅 안에서** 후보를 보고 고른다. macOS Preview 팝업은 중복이니 `EASEL_QUIET=1`로 끄는 걸 권장.
4. **사람이 채팅에서 직접 픽** — 비평/랭킹 없음, 판단은 사람. 고른 번호로 `continue --pick <n>`.

## 중요
- **느리다**: codex 1장당 60~110초, 라운드당 수 분. → 반드시 `run_in_background`로 호출하고 완료 알림을 기다려라.
- **후보 미리보기 = 채팅에 `Read`**: 생성이 끝나면 후보 PNG를 `Read` 도구로 읽어 채팅에 띄운다(사용자가 채팅에서 보고 픽). Preview.app 팝업 대신이므로 `EASEL_QUIET=1`과 함께 쓴다. 별도 위젯/HTML 불필요 — `Read`가 네이티브로 이미지를 표시한다.
- 라운드 완료 시에만 체크포인트라 어디서 멈춰도 `continue`로 재개.
- 옵션(env): `EASEL_N`(발산,3) `EASEL_M`(수렴,2) `EASEL_RUNS`(저장위치) `EASEL_QUIET`(알림끄기).
